# Doubletap 면접 시연 대본

목표는 "도구를 보여주는 것"이 아니라 **"이 사람은 자기 측정을 의심할 줄 안다"** 를 보여주는 것입니다.
결함을 찾는 도구는 흔합니다. 자기가 만든 오탐을 스스로 찾아내고 그 비율을 공개하는 사람은 드뭅니다.

---

## 준비 (면접 전날)

```bash
git clone https://github.com/GlobalMatchHub/doubletap.git && cd doubletap
npm install && npm run setup
node --no-warnings src/cli.ts demo --fast     # 리허설, 약 35초
```

터미널 글자 크기를 키워두십시오. 화면 공유에서 기본 크기는 안 보입니다.

---

## 1. 문제 제기 (말로만, 40초)

> "AI 에게 환불을 시킵니다. 환불은 처리됐는데 응답이 유실됩니다.
> AI 입장에서 '됐는데 답을 못 받은 것'과 '아예 안 된 것'은 구분이 안 됩니다.
> 그래서 다시 시도하고, 고객은 두 번 환불받습니다.
>
> 은행은 2000년대에 이걸 풀었습니다. 멱등키입니다. 저는 결제 연동을 10년 했고
> 매일 다룬 문제입니다. 그런데 AI 도구 판에는 그게 없습니다."

여기서 `idempotentHint` 를 꺼냅니다.

> "MCP 규격에는 도구가 스스로 '나는 두 번 불러도 안전하다'고 선언하는 플래그가 있습니다.
> 게이트웨이가 그걸 읽고 재시도 여부를 판단합니다.
> **그게 참인지 검사하는 곳이 아무 데도 없습니다.**"

---

## 2. 시연 (35초, 화면 공유)

```bash
node --no-warnings src/cli.ts demo --fast
```

**출력이 나오기 전에** 이 말을 먼저 하십시오. 이게 시연의 핵심입니다.

> "지금 도구 3개짜리 서버를 검사합니다. **정답을 먼저 말하고 시작합니다.**
> 하나는 진짜 멱등해서 통과해야 하고,
> 하나는 멱등하다고 선언해놓고 재시도마다 티켓을 새로 만들어서 위반이 나와야 하고,
> **세 번째가 미끼입니다.** 호출마다 감사 로그를 한 줄씩 씁니다.
> 상태는 매번 바뀌지만 효과가 두 번 일어난 게 아니라 두 번 요청받았다고 기록한 겁니다.
> 이건 잡으면 안 됩니다."

출력이 `as predicted` 세 줄로 끝나면:

> "예측대로입니다. 그리고 **세 번째, 미끼를 안 잡는 게 중요합니다.
> 제 도구의 예전 버전은 저걸 결함이라고 신고했습니다.**"

---

## 3. 진짜 이야기 (90초) - 여기가 본론입니다

> "공개된 npm MCP 서버 284개를 전수 검사했습니다.
> 처음 결과에 계약 위반이 9건 나왔습니다. **그중 8건이 제 오탐이었습니다.**"

여기서 한 번 더 세게 갈 수 있습니다.

> "그리고 더 나쁜 게 있습니다. **보안 문제를 고치다가 새 오탐 119건을 만들었습니다.**
> 가로채기 코드를 대상이 덮어쓰지 못하게 매번 복원하도록 바꿨는데,
> 그 함수가 네트워크 로그도 같이 비우고 있었습니다.
> 로그가 줄어드는 걸 제가 적대적 서버 대비로 만든 탐지기가 잡았고,
> 결과적으로 '재시도가 아무것도 안 보냈다 = 서버가 중복 제거했다'로 뒤집혔습니다.
> **119개 서버를 안전하다고 잘못 발표할 뻔했습니다.** 손으로 하나 확인해보니 정반대였습니다.
> 테스트가 잡은 게 아니라 숫자가 이상한 방향으로 움직여서 잡았습니다."

원인을 설명합니다.

> "제가 서버에 가짜 자격증명을 주입하는데, 어떤 서버가 그 값을 **파일 이름으로** 써서
> 로그를 남겼습니다. 그 로그가 호출마다 커지는 걸 제가 '도구가 상태를 바꿨다'고 읽었습니다.
> 제가 남긴 발자국을 남의 결함으로 신고할 뻔했습니다."

고친 방식을 말합니다. 여기서 급이 갈립니다.

> "끝에서 필터로 걸러내지 않았습니다. 합성한 값에 마커를 박고
> **그 마커가 든 경로는 오라클이 아예 상태로 세지 않게** 했습니다.
> 하니스가 자기 발자국 때문에 만들어내는 발견이 구조적으로 불가능해집니다."

그리고 결론을 먼저 내주십시오.

> "지금까지 이 도구가 만든 오탐이 5종 145건입니다. **진짜 발견보다 많습니다.**
> 그 표를 README 최상단에 실었습니다.
> 남의 패키지 결함을 실명으로 공개하는 도구라면 자기 오탐률부터 밝혀야 한다고 봤습니다."

## 4. 예상 질문과 답

**"오탐이 그렇게 많으면 결과를 믿을 수 있나?"**
> "그래서 두 가지를 합니다. 하나는 `verify` 로 같은 시드를 두 번 돌려 508개 레코드 중
> 503개가 동일함을 매번 증명합니다. 나머지 5개는 서버가 내려주는 파일 시각이고
> 자동으로 학습해서 마스크에 넣습니다.
> 다른 하나는 수정을 넣은 뒤 **발견 수치가 안 변하는지** 봅니다.
> 안 변했다는 게 그 수치를 믿을 유일한 근거입니다."

**"동시성 검사는 왜 다 통과인가? 검사가 안 도는 것 아닌가?"**
> "정확히 그 질문 때문에 `selftest` 를 만들었습니다.
> 2초짜리 호출 2개가 순차 4.0초, 동시 2.0초로 처리되는 걸 매번 측정합니다.
> 겹치지 않으면 통과만 잔뜩 나오면서 아무것도 증명 못 하니까요.
> **자기 전제를 증명 못 하는 하니스는 남의 결함을 보고할 자격이 없습니다.**"

**"악의적인 서버도 잡나?"**
> "아닙니다. 적대적 서버로 시험했습니다. 격리는 뚫리지 않았지만
> **서버가 자기 요청 로그를 위조하는 건 막지 못합니다.**
> 프로세스 안에서 도는 코드는 그 프로세스에게 비밀을 지킬 수 없습니다.
> 삭제는 탐지하게 만들었고, 위조는 못 막는다고 README 에 썼습니다.
> 이건 부주의한 서버에 대한 증거이지 적대적 서버에 대한 증명이 아닙니다."

**"왜 HTTP 전송은 안 만들었나?"**
> "만들 뻔했습니다. 69개 서버가 'stdio 가 아님'으로 걸려서 큰 대상군으로 보였거든요.
> 24개를 표본으로 확인했더니 **거의 전부 포트를 안 엽니다.** HTTP 서버가 아니라 그냥 멈춰 있는 겁니다.
> 만들어도 안 열립니다. 측정하고 안 만들었고, 그 수치를 README 에 남겼습니다."

## 하지 말 것

- census 를 라이브로 돌리지 마십시오. 몇 시간 걸립니다.
- 결함 개수를 자랑하지 마십시오. 오탐 이야기가 훨씬 강합니다.
- "MCP 서버들이 엉망이다" 로 말하지 마십시오.
  대부분은 모든 HTTP 클라이언트의 기본 동작이고, 규격이 요구하지 않는 일을 안 한 것뿐입니다.
  실명으로 공개한 이상 그 톤을 지켜야 합니다.
